# 漫游与实测

## 从参考录屏到可逆滚动

从录屏开头、形态转换前后和室内停留处取帧。逐处记下相机位置与朝向、图纸或墙体显隐、家具何时能读清。若附件尚未读到，只把能观察到的部分写成参考结论。

若参考片由平面过渡到空间线稿、再进入室内，选一扇窗或门框作为共同参照。滚动途中停下或回退，都应能辨认这处开口。

将滚轮或单指纵向滑动累加成目标进度，在渲染帧中平滑逼近。渲染结果由当前进度计算，回退即可恢复先前的图纸、家具可见性及相机。图纸与模型共用坐标，转场时能看见同一扇门对齐。总览、平面、临门、室内可以作为四个连续阶段，章节停靠点按住宅动线取舍。实体路径要经过门洞与平台，特别检查样条插值在转角处是否切墙。

在总览中横拖可旋转住宅，在导览中纵滑可推进镜头。自由行走时，拖动只转头。切到人眼视角时选当前可站位置，靠近墙体时平移到相邻的合法落点。提供键盘移动与拖动环顾，触屏让方向摇杆和另一根手指各自跟踪指针。打开房间选择时清空移动输入。渲染能力不足时仍可从页面打开原图。

## 折返楼梯与可达性

- 楼板留出梯井。为每一梯跑及平台提供真实的行走面高度。上下两跑投影靠近时，根据进梯方向、所在梯跑和上一帧脚底标高选择连续面。逐步碰撞，允许沿障碍滑动，人眼高度随脚下地面变化。
- 房间入口要同时满足两件事。从平面图直达后能站稳，从这层的入户门或楼梯平台也能走到。只点选房间会漏掉被家具封住的门洞。
- 多个房间可用 [check_rooms.js](../scripts/check_rooms.js) 做四邻域搜索。把它注入测试页，用项目自己的静态通行查询接入。坐标以米为单位，边界按 `[最小 x, 最小 z, 最大 x, 最大 z]` 填写。示例如下，`walkableAt` 代表项目中已考虑人物半径、层高和墙体的函数。

```js
const report = checkWalkthroughRooms({
  floors: [{
    id: 'ground',
    bounds: [0, 0, 6, 4],
    start: [0.7, 2],
    rooms: [{name: '客厅', at: [4.2, 2]}]
  }],
  canStand: (floor, x, z) => walkableAt(floor, x, z),
  step: 0.075
})
```

若通行还取决于行进方向，可另传纯函数 `canCross(floor, x1, z1, x2, z2)`。脚本返回 `ok` 以及每层 `issues` 中有问题的入口名和原因。狭窄通道可缩小网格复查。搜索检验同层通行，跨层另用真实移动逻辑从楼梯下口经过平台、走到上层，再原路返回，并核对各层脚底标高。导览的室内区段也应密集采样，标出发生碰撞的进度和坐标。

## 在同一个位置辨认四季

保持同一套建筑和家具坐标。按季节分别控制太阳方位与色温、天空和远景、落叶树冠、常绿植物、地面、灯具亮度以及少量软装。让雪只出现在屋外和暴露面，保留落叶后的枝干。窗外植物、近处投影和窗内灯色应相互呼应。更新共享材质和局部灯光。连续点击不同季节时，从正在显示的状态开始过渡。

从可看到窗内外的固定机位依次切换，保存四张实景作对照，同时检查切换前后的人物位置、相机朝向、楼层和模式。再在导览模式切季节，看进度是否保留。在窄屏重复进入、移动、环顾及反向滑动，检查压住摇杆的手指是否干扰视角。区分浏览器触屏模拟与实际设备的测试结果。

## 离线交付

将 HTML 入口、项目源码、许可、必要素材与选定预览整理进暂存目录。声明单文件交付时，用本地文件模式打开，关闭网络后重新加载并操作图纸、季节和漫游，看实际资源请求及三维画面。分享的预览使用交付网页的截图。

从任意位置运行下面的命令，脚本路径换成此 Skill 下的实际路径。带 `--rebuild` 的用法适用于接受一个输出 HTML 路径的 Python 构建器，且构建结果可重复。脚本会解压新包，在干净目录里重建并比对入口。其他构建方式可省略该参数，按项目原有命令在解压目录复验。

```sh
python3 scripts/package_walkthrough.py "交付暂存" "住宅漫游.zip" --entry "住宅.html" --rebuild "源码/build.py"
```

交付时给出能直接打开的 HTML 与 ZIP，说明重建和浏览器操作各验证到了哪一步。
